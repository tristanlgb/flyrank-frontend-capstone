# AI-Assisted Workflow Comparison

For FE-03, I built the same user settings form in two independent branches. Round One used the single prompt, “Create a settings form in React.” I accepted the generated result with minimal intervention. Round Two started from the same `main` branch in a fresh session and used a detailed specification that referenced the project files, required an implementation plan, defined expected behavior, and requested tests plus verification commands.

The Round One branch produced a form quickly, but the implementation was only superficially complete. In `src/components/SettingsForm.tsx`, the inputs used placeholders instead of visible labels, the checkbox had no programmatic label association, and the form relied on an `alert` for feedback. There was no validation for empty values, malformed email addresses, or a one-character display name. Text fields were not trimmed, the submit button never entered a loading state, and repeated clicks could invoke submission multiple times. The branch also contained no tests, so reviewing correctness required manual browser checks.

The Round Two diff added a Zod schema, React Hook Form, strict value types, inline validation messages, `aria-invalid`, `aria-describedby`, and an `aria-live` success message. It also normalized text before submission and disabled the submit button while an asynchronous save was pending. The test file verifies valid normalized output, invalid email handling, minimum display-name length, and submission state.

One AI mistake I caught during Round Two was an incorrect accessibility reference: the email input initially pointed to the display-name error ID in `aria-describedby`. The UI looked correct, but a screen reader would have announced the wrong message. I corrected the ID and reviewed every input/error relationship before accepting the code. This was a useful reminder that passing visual review is not enough.

Round One took about 8 minutes to generate and approximately 25 minutes to inspect and repair mentally because there was no automated verification. Round Two took about 15 minutes to specify and generate, followed by roughly 8 minutes of review. Although the second prompt was slower to write, it reduced total review effort and produced code that was easier to trust. The resulting project rules now require typed schemas, accessible labels, behavioral tests, input normalization, and successful test, type-check, and build commands before AI-generated form code is accepted.
