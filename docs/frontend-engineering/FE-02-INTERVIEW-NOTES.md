# FE-02 — AI Interview Notes

These decisions summarize the questions used to narrow the capstone before
writing `SPEC.md`.

## What is the single claim?

I can build, deploy, and verify an accessible AI-assisted frontend workflow.

## Who needs proof?

A FlyRank mentor or junior-frontend hiring reviewer who can inspect the live
result and repository.

## What should that person do?

Try the dynamic mentor flow, then inspect the source and verification evidence.

## What real problem does the project solve?

It gives reviewers traceable evidence behind the phrase “AI-assisted,” and it
helps me detect missing portfolio files or broken public links before
submission.

## What is the narrowest useful AI boundary?

One protected server endpoint for mentor messages. The browser must never hold
the model credential.

## What must remain human-owned?

Final interpretation of portfolio claims, approval of code, publishing,
credentials, and any irreversible action.

## Which stack can I explain and run?

React, TypeScript, Vite, Node.js, Vitest, WebGL, and Vercel. This uses my
existing JavaScript experience and avoids an unnecessary framework migration.

## What was cut?

Private repositories, automatic editing, a database, authentication, persistent
chat history, and a general-purpose chatbot without a configured model.
